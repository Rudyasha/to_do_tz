# Мини тест-план: Infinite Scroll

План проверки будущей пагинации: **15 задач на страницу**. В кейсах текущей загрузки используется лимит 10; это разные сценарии.


## Scope


### Включено

- первая загрузка 15 задач;
- загрузка следующих 15 при скролле;
- отсутствие дублей и пропущенных задач;
- корректный порядок элементов;
- последняя неполная страница;
- отсутствие лишних запросов после окончания списка;
- повторный быстрый scroll;
- задержка и ошибка API;
- работа Create / Edit / Complete / Delete после подгрузки новых страниц;
- работа фильтров All / Active / Completed с загруженными данными.

### Исключено

- нагрузочное тестирование;
- security testing;
- автоматизация;
- детальное UI / pixel-perfect тестирование.

## Виды тестирования

- Functional testing: загрузка первой и последующих страниц.
- Integration/API testing: параметры запросов, response, количество запросов.
- Boundary testing: 15/16, 30/31, последняя страница.
- Negative testing: timeout, API error, offline, повторный scroll.
- Regression testing: CRUD и фильтры после внедрения pagination.
- Exploratory testing: быстрый scroll, смена фильтра во время загрузки, CRUD во время подгрузки.

## Риски

| Риск | Проверка |
| --- | --- |
| Дубли задач | сравнить ID между загруженными страницами |
| Пропуск задач | проверить границы 15/16, 30/31 и последовательность ID |
| Несколько одинаковых запросов | быстро скроллить и проверить Network |
| Нарушение порядка из-за параллельных запросов | замедлить сеть и проверить порядок добавления страниц |
| Бесконечные запросы после конца списка | дойти до последней страницы и продолжить scroll |
| Потеря уже загруженных данных при API error | вызвать ошибку при загрузке следующей страницы |
| CRUD ломается после нескольких страниц | после подгрузки выполнить Edit / Complete / Delete |
| Фильтры работают некорректно с частично загруженным списком | проверить All / Active / Completed после нескольких загрузок |

## Definition of Done

Фича готова к релизу, если:

- первая загрузка возвращает 15 задач;
- каждая следующая загрузка добавляет следующую порцию без дублей и пропусков;
- порядок задач сохраняется;
- повторный scroll не создаёт дублирующих запросов;
- последняя страница и конец списка обрабатываются корректно;
- ошибки и задержки API не ломают уже загруженный список;
- Create / Edit / Complete / Delete продолжают работать после pagination;
- фильтры работают согласно требованиям;
- smoke и regression пройдены;
- нет открытых Blocker / Critical и Major-дефектов, влияющих на основной сценарий infinite scroll.
